# Voltline – Electronics E-Commerce Storefront

A modern, responsive electronics shopping website built with **React 18 + Vite**. It covers Mobiles, Laptops, Microphones and Accessories, with a Myntra-style shopping experience: banners, offers, bestsellers, filters, a product detail page, wishlist, bag, checkout, orders and login / sign up. All data is mock data, so no backend or database is needed.

## Tech stack

- **React 18** (function components and hooks only)
- **Vite 5** for dev server and build
- **Plain CSS** (`src/index.css`) with CSS variables, no UI library
- No router or state library: a small hash router and React Context keep the code easy to explain

## Getting started

Requires Node.js 18 or newer.

```bash
npm run build      # production build in dist/
npm run preview    # serve the production build locally
```

`npm run build:single` produces one self-contained HTML file in `dist-single/` (used for quick previews, not needed for Vercel).

## Adding product images

Every product ships with illustrated images (`src/assets/products/*.svg`: a main image plus 3 gallery views) and every brand has an original logo (`src/assets/brands/`: `<brand>.svg` wide logo and `<brand>-mark.svg` icon). They are generated by `python3 scripts/generate-assets.py`.

To use your own photos, drop a file with the same name in `src/assets/products/` (for example `aurora-x1-pro-5g.jpg`, plus optional `-2`, `-3`, `-4` gallery shots). Photos can be `.jpg`, `.jpeg`, `.png`, `.webp` or `.avif`; if both a photo and an SVG have the same name, delete the SVG. Run `npm run images` to see which products have images. Full guide: `src/assets/products/README.md`. Brand logos work the same way in `src/assets/brands/`.

## Architecture and design decisions

**Component hierarchy.** `main.jsx` wraps `<App/>` in `<StoreProvider/>`. `App` renders the persistent shell (Header, Footer, Modal, Toast) and swaps the current page in the middle. Pages compose small reusable components; for example `ProductCard` is used by Home, Shop, Wishlist and the rows.

**State management.** One React Context (`context/Store.jsx`) holds the shared state and exposes actions: `addCart`, `setQty`, `toggleWish`, `placeOrder`, `cancelOrder`, `login`, `signup`, `setFilter`, `openCat`, `openProduct`, `toast`. Cart totals are *derived* from the cart each render instead of stored, so they can never go out of sync. Page-only state (the image tab, PIN input, payment method, form fields) stays local to its page with `useState`.

**Persistence.** `useLocal` saves the cart, wishlist, orders, user and accounts to `localStorage`, so they survive a refresh. Reads and writes are wrapped in try/catch because storage can be unavailable.

**Routing.** `router.js` reads the part after `#` (`home`, `shop`, `product`, `wishlist`, `bag`, `checkout`, `orders`, `login`). It avoids a dependency and works on any static host with no rewrite rules. The selected product id and variant live in the store. To get URLs like `/product/6`, swap in React Router; the pages would not need to change.

**Product variants.** Storage options (phones, laptops) or colours (mics, accessories) are defined in `data/products.js`. A variant multiplier changes the price, and each cart line is keyed `productId|variantIndex` so the same product in two variants stays as two lines.

**Filtering and sorting.** `Shop.jsx` filters the catalog and sorts it on each render with plain array methods, which is fast enough for a mock catalog. The filter state sits in the store so the header search, footer links, brand tiles and mega-menu can all set it.

**Responsive design.** A mobile-friendly layout is built with CSS grid and flexbox. At about 1000px the nav becomes a hamburger menu, the filters become a toggle panel, and the product, bag and checkout layouts stack. At about 560px the product grid drops to two columns and the header icons shrink to icons only. Colours and spacing come from CSS variables.

**Accessibility.** Buttons and inputs carry labels, links are keyboard-focusable, focus rings are visible, the Escape key closes popups, and the banner slider respects `prefers-reduced-motion`.

## Animations

All motion is CSS (keyframes and transitions) plus one small component, so it stays light and easy to explain.

- **Page transitions:** each page fades and slides up when you navigate (`.page`, keyed by route in `App.jsx`).
- **Scroll reveal:** home sections fade in as they enter the viewport (`components/Reveal.jsx`, IntersectionObserver).
- **Staggered cards:** product grids in Shop and Wishlist rise in one after another.
- **Hero banner:** slides cross-fade, the text slides in and the artwork pops and floats.
- **Micro-interactions:** card lift and image zoom on hover, heart pop, bag and wishlist badge bump, button press, popup scale-in, mega-menu fade, filter chip pop, success check pop.
- **Accessibility:** `prefers-reduced-motion` turns all animation and transitions off.

## Mock authentication (important)

Login and sign up are **front-end only**. Accounts are kept in the browser's `localStorage` and passwords are stored in plain text. This is fine for a demo with no backend, but a real application must hash passwords on a server and use secure sessions or tokens.

## Deploying to Vercel

1. Push the project to a **private** GitHub repository (see below).
2. In Vercel choose **Add New, then Project**, and import the repository.
3. Framework preset: **Vite**. Build command `npm run build`, output directory `dist`. Vercel detects these automatically.
4. Click **Deploy**, then copy the live URL into this README.

No environment variables are needed, and the hash router needs no rewrite rules.

## Known limitations and next steps

- No backend: orders, payments and accounts are simulated.
